# ADR 0013: SHAによる同一性と数値再計算の一致を分離する

- 状態: 承認
- 決定日: 2026-08-12
- 比較契約ID: `simulation-report-cross-platform-v1`
- 対象: 筆記版・音声版の保存済みシミュレーション成果物とCI再計算

## 決定

SHA-256は、計画、ソース、seedを含む保存済み結果、配布ファイル、および音声資産の**バイト列同一性**を確認するために使う。SHA-256の一致を、別のOS・CPU・Node.js版で浮動小数点集計値がビット単位で一致すること、または心理測定上の妥当性の証明とは解釈しない。

保存済みシミュレーションの再計算検証では、JSONのキー、配列長、文字列、真偽値、`null`、整数、非有限数を完全一致とする。整数にはseed、反復数、項目index、選択数、試行数、順位、停止数などが含まれるため、実験経路や判定の離散的な変化は許容しない。有限の非整数だけ、次の固定契約で比較する。

\[
|x_{new}-x_{stored}| \le 10^{-12} + 10^{-13}\max(|x_{new}|, |x_{stored}|).
\]

この許容差は、GitHub Actionsで実測したmacOS/arm64とLinux/x64間の最大既知差 `9.094947017729282e-13` を包含する。さらに、保存済み結果中の正のMonte Carlo標準誤差の最小値は約 `0.001998` であり、絶対許容差はその約20億分の1以下である。したがってこれは統計的な判定境界を緩める値ではなく、倍精度演算順序の差だけを扱う工学的再計算許容差である。新たにこれを超える差が出た場合、許容差を自動的に拡大せず原因を再調査し、契約変更なら新IDを発行する。

## 項目バンクの二つの同一性

項目バンクには二つのSHA-256を持たせる。

1. `itemBankLogicalSha256`: UTF-8 BOMと改行形式を除去し、固定列順、行順、文字列値、IEEE-754で解釈した有限数値を版付きJSONへ正規化した論理内容のSHA-256。
2. `itemBankArtifactSha256`: `public/jacet_parameters.csv` の配布バイト列そのもののSHA-256。

論理SHAは、CRLF/LF、BOM有無、`1.0`と`1.00`のような等価な数値表記によって変わらず、項目文字列、行順、列順、項目パラメータが変われば変わる。成果物SHAは、実際に配布・保存したファイルの完全同一性を確認する。旧シミュレーション結果の `itemBankSha256` は成果物SHAを指す既存スキーマとして保持し、過去成果物を書き換えない。研究実施ログには新しい論理スキーマID、論理SHA、成果物SHAを併記する。

## 検証上の意味

- SHA一致: 指定されたバイト列が同じであり、改変・取り違えがない。
- 離散値の一致: seed付き手続の選択、計数、構造、判定が同じ。
- 連続値の許容差内一致: 異なる実行環境でも保存済み集計を数値的に再現した。
- いずれも単独では、モデル適合、母集団一般化、得点妥当性、0–8000尺度の解釈を保証しない。

CIはこれらを別々に失敗させ、エラーメッセージにJSON pathと差を表示する。将来の結果スキーマでは比較契約IDもprovenanceへ直接保存する。

再計算環境は `.nvmrc` のNode.js `24.9.0`へ固定し、CIとdeployは同ファイルを参照する。ただし、Node.js版の固定だけではOS、CPU、標準数学ライブラリ、演算順序まで同一にはならないため、クロスプラットフォーム数値比較契約は維持する。
