# ADR 0013: SHAによる同一性と研究判断の再現性を分離する

- 状態: 承認
- 決定日: 2026-08-12
- 比較契約ID: `simulation-research-decision-v1`
- 対象: 筆記版・音声版の保存済みシミュレーション成果物とCI再計算

## 決定

SHA-256は、計画、ソース、seedを含む保存済み結果、配布ファイル、および音声資産の**バイト列同一性**を確認するために使う。SHA-256の一致を、別のOS・CPU・Node.js版で浮動小数点集計値がビット単位で一致すること、または心理測定上の妥当性の証明とは解釈しない。

保存済みシミュレーションを別環境で再計算するCIゲートは、事前に定義された研究判断が不変かだけを検査する。具体的には、候補・方法・実験のID、各ゲートの `true` / `false` / `null`、失敗ゲート名、合格候補、採否、および次の手続きを表す決定を保存結果と完全一致させる。候補数やセル対応はこの判断射影の構造として検査し、セルの実数値はSHAで固定された計画と配列位置から同定する。

bias、RMSE、被覆率、平均、Monte Carlo標準誤差などの連続診断値は、クロスプラットフォームCIの合否には使わない。共通の数値許容差を定めても、それは計算機差の大きさを事後的に追うだけで、測定上の判断境界を表さないからである。再計算値が多少異なっても全ゲート判断が同じなら研究上の結論は再現している。境界をまたいでゲートが変わればCIを失敗させ、原因と判断の頑健性を調べる。

推定量感度研究と露出制御研究は探索的記述であり、保存成果物に事前定義された採否ゲートがない。この2件についてCIは、成果物・計画・項目バンク・ソースのSHAとスキーマを検査するが、事後的な閾値を作って再計算値を合否判定しない。計算手続自体の決定性と数式は小規模unit testおよび独立fixtureで検査し、成果物を更新するときは明示的なシミュレーション実行とレビューを必要とする。

## 項目バンクの二つの同一性

項目バンクには二つのSHA-256を持たせる。

1. `itemBankLogicalSha256`: UTF-8 BOMと改行形式を除去し、固定列順、行順、文字列値、IEEE-754で解釈した有限数値を版付きJSONへ正規化した論理内容のSHA-256。
2. `itemBankArtifactSha256`: `public/jacet_parameters.csv` の配布バイト列そのもののSHA-256。

論理SHAは、CRLF/LF、BOM有無、`1.0`と`1.00`のような等価な数値表記によって変わらず、項目文字列、行順、列順、項目パラメータが変われば変わる。成果物SHAは、実際に配布・保存したファイルの完全同一性を確認する。旧シミュレーション結果の `itemBankSha256` は成果物SHAを指す既存スキーマとして保持し、過去成果物を書き換えない。研究実施ログには新しい論理スキーマID、論理SHA、成果物SHAを併記する。

## 検証上の意味

- SHA一致: 指定されたバイト列が同じであり、改変・取り違えがない。
- 判断一致: 固定計画・seed・ソースによる再計算で、事前定義した研究上の採否が変わらない。
- 連続診断値: 効果の大きさ、Monte Carlo誤差、境界からの距離を読むために保存するが、別環境との完全一致自体をゲートにしない。
- いずれも単独では、モデル適合、母集団一般化、得点妥当性、0–8000尺度の解釈を保証しない。

再計算環境は `.nvmrc` のNode.js `24.9.0`へ固定し、CIとdeployは同ファイルを参照する。これは実行環境を記録し差異を減らすためであり、OS、CPU、標準数学ライブラリ、演算順序の完全一致を要求するためではない。
